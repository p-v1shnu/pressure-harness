# ออกรีลีส

```
# 1. ตั้งเวอร์ชันใน pyproject.toml ให้ตรงกับที่จะ tag (ตัด .dev0 ออก)
# 2.
git commit -am "release 0.1.0"
git tag v0.1.0
git push --tags
```

CI จะ build, smoke test, แล้วสร้าง GitHub Release ให้เอง พร้อม:

- `ph-windows-x64.exe` และ `ph-linux-x64` — ไฟล์เดียว ไม่ต้องมี Python บนเครื่องปลายทาง
- `SHA256SUMS`
- SBOM (CycloneDX)

## ทำไม tag ต้องตรงกับ `pyproject.toml`

workflow จะล้มเหลวถ้าไม่ตรง — เพราะถ้า `ph --version` บอกอย่างหนึ่งแต่หน้าดาวน์โหลด
บอกอีกอย่าง คนที่มาไล่บั๊กอีกหกเดือนข้างหน้าต้องมานั่งหาว่าอันไหนโกหก

## เวลาส่งไฟล์ให้คนอื่น

ส่ง**ลิงก์หน้า release** ดีกว่าส่งไฟล์ทางแชท — เพราะ checksum อยู่บนหน้านั้น
ซึ่งเป็นคนละช่องทางกับตัวไฟล์ ถ้าส่ง exe กับ checksum ในแชทเดียวกัน
มันพิสูจน์อะไรไม่ได้เลยกับคนที่ยึดแชทนั้นได้

และบอกผู้รับล่วงหน้าว่า **SmartScreen จะเตือน** เพราะเราไม่ได้เซ็นโค้ด (ตัดสินใจไว้แล้ว
ดู PRD §17) — ให้เขาเทียบ checksum ครั้งแรก ดีกว่าปล่อยให้ชินกับการกดข้ามคำเตือน
